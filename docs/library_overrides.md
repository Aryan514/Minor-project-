# Library overrides: where default library behaviour would bypass the arbiter or break an invariant

This file is evidence for **N1**. The two protocol libraries are well suited to a single-interface tool. Used as-is
in a dual-interface tool, several of their defaults would create a **second owner of state**, a **path around the
arbiter**, or would **break a consistency invariant** (I1–I6). Each row says what the library does by default (from
its source, see `library_notes.md`), why that is a problem here, and how we override it. All overrides live in
`equipment/gem_adapter.py` and `equipment/opcua_adapter.py`; the core and the arbiter are library-free.

Legend: **Bypass** = a command could change state without `arbiter.decide`; **2nd state** = the library keeps its
own copy of equipment state that could diverge from the core; **I1–I6** = invariant at risk (`CLAUDE.md` §11).

## secsgem 0.3.0 (GEM door)

| ID | Library default (file) | Risk | Our override | Verified by |
|---|---|---|---|---|
| O1 | `RemoteControlCapability._on_s02f41` (`gem/remote_control_capability.py`) replies **HCACK 4 "finish later"** to every known RCMD *before* running `_on_rcmd_<NAME>`, then triggers a library CEID. | **Bypass**: the command would run without the arbiter, and the host would never see HCACK 2/5. **I5**: the loser of a conflict could not get the mapped rejection. | `_ChamberGemHandler._on_s02f41` decodes RCMD and calls `core.submit_command(GEM_HOST, rcmd)`. The S2F42 HCACK is the arbiter/core result (0/1/2/5). | CP3 run: LOCAL → HCACK 2, REMOTE → 0, repeat → 5. `test_race.py` covers the core path. |
| O2 | `EquipmentConstantsCapability._on_s02f15` (`gem/equipment_constants_capability.py`) does its own range check and writes the value into the library's `EquipmentConstant.value` (or `on_ec_value_update`, which cannot refuse). | **Bypass** (no authority check) and **2nd state** (library copy of ECID 201). | `_on_s02f15` calls `core.submit_ec_write(GEM_HOST, ecid, value)` per item. S2F16 EAC is the core result (0/1/2/3). `on_ec_value_request` reads the core, so S2F13 never sees a library copy. | CP3 run: `--set-limit 81` → EAC 3, `21` → EAC 0 (CEID 1006 then seen on both doors). |
| O3 | `StateModelsCapability` owns a full GEM `ControlStateMachine` that the **host** can change with S1F15/S1F17 (`gem/state_models_capability.py`). `GemEquipmentHandler.on_connection_closed` also switches it offline and back online. | **Bypass + 2nd state**: the host could change control state without the operator or the arbiter, and SVID 1002 would report a control state that differs from the core's SVID 2 (**I4**). | `_on_s01f15`/`_on_s01f17` call `core.set_control_state(GEM_HOST, …)`. The arbiter refuses (control state is OPERATOR-only, decision D3), the attempt is audited, and CEID 1005 goes to both doors. Replies: S1F18 ONLACK 1/2, and S1F0 abort for S1F15 (OFLACK has no refusal code). `on_connection_closed` is a no-op. The library state machine is never consulted. | `test_arbiter.py::test_operator_only_actions`, `test_core.py::test_no_bypass_deny_all`. |
| O4 | Pre-registered defaults: SVIDs 1001–1005 (incl. **1002 ControlState** from the library machine), ECIDs 1–2, CEIDs 1/2/3/20/21, RCMDs START/STOP with library CEIDs. | **2nd state** visible to the host (SVID 1002 vs SVID 2 → **I3/I4**). Events the core never audited (**I1/I6** oracle incomplete). | `GemAdapter._configure_handler` clears all these dicts and registers exactly the IDs from `config.py`. | CP3 `--status` (S1F3) returns only SVIDs 1–5. |
| O5 | `CollectionEventCapability.trigger_collection_events` starts **one new thread per event**, reads report values **at send time** through the SV/DV callbacks, and silently skips CEIDs that are not linked/enabled. | **I2** (two threads can reorder events), **I3** (a sample event could carry a later temperature), **I6** (silent drop, no record). | The GEM door never calls it. Its single dispatcher worker builds each S6F11 from the **event-time payload frozen by the core** (incl. DVID 101 = seq) and sends it synchronously. Before sending, it logs `dropped_no_link` / `dropped_disabled`; after, `sent` / `error`. | CP3 run: 51/51 events received, in order, 0 duplicates. Every S6F11 carries EventSeq. |
| O6 | `AlarmCapability.set_alarm/clear_alarm` send S5F1 with the fixed `Alarm.text`, keep their own `Alarm.set` flag, and trigger extra CEIDs `ce_on`/`ce_off`. | **I1/I3**: no seq in the alarm message, so it cannot be joined to the audit log. **2nd state**: library alarm flag. | The door sends S5F1 itself from the dispatcher (ALCD bit 0x80 on set, ALTX `… seq=<n>`), and only mirrors `alarms[5001].set` from core notifications for S5F5/S5F7 answers. `ce_on/ce_off` are unused. | CP3 run: `ChamberOverTemp SET T=26.18 seq=52` / `CLEAR … seq=67`, same seqs as the audit. |
| O7 | S2F33 (define report) only accepts VIDs that are SVIDs or DVIDs. | CEID 1006 is specified to report ECID 201. Without a fix that report could not be defined (**I3** for EC changes). | ECID 201 is also registered as a data value with the same id. Its event-time value comes from the core payload. | CEID 1006 records in `gem_host.jsonl`: `{'201': 21.0}`, `{'201': 45.0}`. |
| O8 | `GemHandler.on_connection_closed` is **never called** in 0.3.0 (leftover hook), so the GEM communication state stays COMMUNICATING after the host disconnects. | Events after a disconnect would be "sent" into a dead link instead of being attributed as `dropped_no_link` (**I6**). The UA CommunicationState mirror would be wrong (**I4**). | `GemAdapter` subscribes to the HSMS `disconnected` event, calls `communication_state.communicationfail()`, and reports the link to the core (`set_gem_link`, audited, mirrored to UA). | CP3 audit: COMMUNICATING/NOT_COMMUNICATING alternate with each session. Events with no host are logged `dropped_no_link`. |
| O9 | `TcpServerConnection.__server_thread` (`common/tcp_server_connection.py`): (a) after `accept()` it calls `shutdown()` on the listening socket, which raises WinError 10057 on Windows, so the socket is never closed; (b) when `disable()` closes the socket, the thread dies with `UnboundLocalError` before clearing `_stop_server_thread`, and `disable()` waits forever. | Rule 10 / robustness: tracebacks after every connect, a leaked listening socket, and an equipment process that **cannot shut down** (ports 4840/5000/5100 stay taken). | `_ServerConnection` (via `_HsmsSettings.create_connection`) runs the library function unchanged and adds the cleanup it skips: always close the listening socket and clear `_stop_server_thread`. | CP3: three reconnects work. `quit` exits with and without a connected host. 0 tracebacks, ports free afterwards. |

## asyncua 1.1.8 (OPC UA door)

| ID | Library default | Risk | Our override | Verified by |
|---|---|---|---|---|
| O10 | A variable created with `set_writable()` is written straight into the address space by the Write service. A `value_setter` can intercept but can only refuse with a request-level ServiceFault, and it also fires for the server's own writes (`server/address_space.py`). | **Bypass + 2nd state**: a client write to TempHighLimit would change the UA copy without the arbiter, and UA would then disagree with GEM/core (**I3/I4**). | `TempHighLimit` is read-only (`set_read_only`). Writes go through the method `SetTempHighLimit(value)` → `core.submit_ec_write(UA_CLIENT, …)`, which returns the mapped per-call StatusCode (decision D10). | CP2: `--set-limit 99` → BadOutOfRange, `20` in LOCAL → BadUserAccessDenied. |
| O11 | Method callbacks may be `async` and then run **inside** the event loop. | Calling the core (thread lock) from inside the loop could stall all UA traffic while another door holds the lock. | Start/Stop/SetTempHighLimit are **synchronous** callbacks. asyncua runs them in its thread pool (`MethodService._run_method`). | CP2 method calls while the listener was subscribed. |
| O12 | `EventGenerator` holds **one mutable event object** per type, and `trigger()` is async. Two concurrent triggers could mix fields of two events. | **I3** (fields of seq N with payload of seq N+1). | All UA events are fired by the single UA dispatcher worker, one at a time (`run_coroutine_threadsafe(...).result()`), in seq order (D12). | CP2 run: 24/24 events, ordered, CEID/EventSeq/Payload consistent. |
| O13 | Events are delivered only to monitored items on the **emitting node**, and silently go nowhere if nobody subscribed. | **I6**: losses would be invisible. | Every generator uses `emitting_node=Chamber1Tool`. Before triggering, `_has_event_subscriber()` decides between `sent` and `dropped_no_link` in `ua_adapter_send.jsonl`. | CP2: 27 `dropped_no_link` before the client subscribed, 25 `sent` after. |
| O14 | No server-side Alarms & Conditions state machine (Acknowledge/Confirm not implemented). | **N2 gap**, not a bypass. A UA Acknowledge would not reach the core anyway. | Not overridden. Documented in `limitations.md`. The alarm state is owned by the core and only *reported* via OffNormalAlarmType events. | — |
